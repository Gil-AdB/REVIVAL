## A. Watertight tessellation with displacement

Five independent sources — a hardware spec, two SIGGRAPH papers, a production library and a
GPU vendor's postmortem — converge on the same rule, and it decomposes cleanly into three
parts. **Watertightness is a property of positions only.** Split shading normals do not break
it; near-coincident *positions* do. Conflating the two is what produces hairline slits.

**R1 — Topological identity.** A point on a shared border must exist once in the output and
be referenced by index from both sides. OpenSubdiv's Bfr tutorial states the construction
verbatim: *"topologically watertight, i.e. resulting points evaluated along shared edges or
vertices are shared and not duplicated. Since Tessellation provides points around its
boundary first, the evaluated points for shared vertices and edges are identified when
constructed and reused when shared later"*
([bfr_tutorial_2_2.cpp](https://github.com/PixarAnimationStudios/OpenSubdiv/blob/release/tutorials/bfr/tutorial_2_2/bfr_tutorial_2_2.cpp)).
Evaluate once, copy — do not recompute and hope.

**R2 — The edge owns its sample count.** DiagSplit (Fisher, Fatahalian, Boulos, Akeley, Mark
& Hanrahan, SIGGRAPH Asia 2009, [graphics.stanford.edu/papers/diagsplit](http://graphics.stanford.edu/papers/diagsplit/))
is the canonical statement, verbatim from the abstract: *"uses a dicing scheme that supports
unique tessellation factors for each subpatch edge. Edge tessellation factors are computed
using only information local to subpatch edges. These modifications allow all subpatches
generated by DiagSplit to be processed independently without introducing T-junctions or mesh
cracks and without incurring the tessellation overhead of binary dicing."* Both sides agree
because neither side decides.

**R3 — Bit-identical arithmetic.** The Direct3D 11.3 Functional Specification §11.7.13
([microsoft.github.io/DirectX-Specs](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm))
is the most precise primary source found, verbatim:

> "A shared edge has to generate identical domain locations for crack free tessellation to
> be possible… hardware tessellation on any given edge must always produce a distribution
> of domain points symmetric about the edge based on the TessFactor for that edge alone.
> Second, the parameterization of each domain point… must produce 'clean' values in the
> space [0.0 … 1.0]. 'Clean' means that given a domain point on one side of the edge, with
> the parameter for that edge (say it is U) in [0 … 0.5], the mirrored domain point produced
> on the other side, call it U' in [0.5 … 1.0] will have a complement satisfying (1−U') == U
> exactly."

The spec's design-goals list states the invariant as an implementable test: *"Care must be
taken with floating point values generated so that generated value == (1 − (1 − generated
value))."* §11.7.14 adds the mechanism: domain locations are computed in **fixed point with
16 fraction bits** and only then converted to float32, because *"uniform spacing of
representable values across the [0…1] range… facilitates the symmetry and watertightness
issues discussed above."* For a CPU bake this transfers directly: generate shared-edge
parameters as exact rationals `i/n` in integer arithmetic, never by float accumulation.

The spec is also blunt that hardware only gets you so far: *"The domain locations are water
tight across a boundary if identical level of detail is used, otherwise the hardware plays no
role in ensuring crack free surfaces."*

**Corroboration.** Moreton, *"Watertight Tessellation using Forward Differencing"*, Graphics
Hardware 2001 ([doi:10.2312/EGGH/EGGH01/025-032](https://diglib.eg.org/handle/10.2312/EGGH.EGGH01.025-032))
— per the EG abstract, conventional forward differencing "is subject to round off error and
cracking", and their algorithm "produces a bit-for-bit consistent triangle mesh across
multiple independently tessellated patches". Nießner, Loop, Meyer & DeRose, *"Feature
Adaptive GPU Rendering of Catmull-Clark Subdivision Surfaces"*, ACM TOG 2012
([abstract](https://graphics.stanford.edu/~niessner/niessner2012feature.html)): *"a variant of
the algorithm which guarantees watertight positions and normals, meaning that even displaced
surfaces can be rendered in a crack-free manner"*; neighbouring patches compute
bitwise-identical boundary values with no inter-patch communication, and where patches sit at
different subdivision levels the parent control points are used.

**The offline/bake equivalent** is Maggiordomo, Moreton & Tarini, *"Micro-Mesh
Construction"*, ACM TOG 2023 ([PDF](https://micromesh.di.unimi.it/micromesh_construction_LOWRES.pdf)).
Verbatim: *"Bit-exact watertightness between displaced base faces is achieved through shared
base mesh vertex positions and displacement vectors, and duplication of displacement values
on shared edges, plus by using a per base face edge decimation control bit to reduce the
number of triangle edge segments by one half along the associated edge."* Note the
three-part structure — shared positions **and directions**, duplicated **height values** on
the shared edge, and an explicit **level-reconciliation bit**. That is R1+R2+R3 in one
sentence, for a bake, not a GPU.

**The most transferable practical technique** is Dudash's "dominant data", GDC 2012, *"My
Tessellation Has Cracks!"*
([NVIDIA PDF](https://developer.nvidia.com/sites/default/files/akamai/gamedev/files/gdc12/GDC12_DUDASH_MyTessellationHasCracks.pdf)).
His diagnosis: *"Two primitives share an edge positionally, but the vertices of that edge
have divergent data (Normal, UV, etc)"*, and crucially *"Only along control edges/vertices.
Interior edges are guaranteed not to crack."* His general solution: *"Ensure the domain
shader is using same input data: Shared Vertices, Shared Edges."* The implementation is a
canonical-owner table built at bake time: *"CPU side pre-process… Generate Packed Listing of
shared position & edges… Arbitrarily pick dominant data: first entry in the list. It really
is that simple."* The safety argument: *"This is safe as we only override along the shared
edge and control vertices. An edge will never crack from itself."*

Dudash also names failure mode 4 explicitly, as **"Intra-material cracking"**: *"Meshes in
games often have multiple materials. Submeshes render as separate draws with separate
textures and UV spaces. No access to neighbor info across seams."* His listed remedies are to
share the buffer, to encode dominant data across the whole submesh group, or to *"Pin
displacement to 0 at edge"*.

**Offline remeshing precedents.** Lee, Moreton & Hoppe, *"Displaced Subdivision Surfaces"*,
SIGGRAPH 2000 ([hhoppe.com/proj/dss](https://hhoppe.com/proj/dss/)) — scalar displacement over
a smooth domain surface in a unified subdivision framework. In REYES, RenderMan's answer was
binary dicing (power-of-two dice rates), which reduces but does not eliminate cracks *between
separate primitives*; the Aqsis wiki's
[Grid Crack Solutions](https://github.com/aqsis/aqsis/wiki/Grid-Crack-Solutions) is a useful
negative result — it rejects independent edge-dicing-plus-stitching because "there will
always be no more than one neighbouring patch" cannot be guaranteed.

**Consumer side.** Even a topologically watertight mesh leaks if the *test* is inconsistent:
Woop, Benthin & Wald, *"Watertight Ray/Triangle Intersection"*, JCGT 2(1), 2013
([jcgt.org](https://jcgt.org/published/0002/01/05/)).

## B. Displacement across hard creases and corners

**The decisive statement is Pixar's**, and it is about exactly failure mode 1. From the
OpenSubdiv subdivision-surfaces documentation
([opensubdiv.org/docs/subdivision_surfaces.html](https://opensubdiv.org/docs/subdivision_surfaces.html)),
fetched and verified verbatim:

> "infinitely sharp creases are really tangent discontinuities in the surface, implying
> that the geometric normals are also discontinuous there. Therefore, displacing along the
> normal will likely tear apart the surface along the crease."

Their recommendation is to *"make the crease semi-sharp"* — i.e. to remove the discontinuity
rather than to displace across it. This is the literature saying, in one sentence, that
"displace along the vertex normal" is not a technique that has a correct version at a hard
corner. The semi-sharp crease apparatus itself is DeRose, Kass & Truong, *"Subdivision
Surfaces in Character Animation"*, SIGGRAPH 98
([doi:10.1145/280814.280826](https://dl.acm.org/doi/10.1145/280814.280826)).

**The mitre formula.** Two planes with unit outward normals **n₁**, **n₂** through a crease
point **p**, each to be offset outward by *d*. Do **not** normalize a bisector. The offset
planes are `n₁·x = n₁·p + d` and `n₂·x = n₂·p + d`; require additionally that the motion be
perpendicular to the crease direction **e**. That is a 3×3 linear system with rows
(**n₁**, **n₂**, **e**) and right-hand side (*d₁*, *d₂*, 0). It is sign-free — it never asks
which side is visible — and it is therefore automatically correct at reflex corners, which is
precisely what a normalized-bisector construction with a wrong-sign partner normal gets
wrong.

Closed form, for equal offsets *d₁ = d₂ = d*, with *c* = **n₁·n₂**:

```
p' = p + d·(n₁ + n₂)/(1 + c)
```

Check: **n₁**·(p′−p) = d(1+c)/(1+c) = d. Magnitude: |p′−p| = d/cos(θₙ/2) where θₙ is the
angle between the normals; equivalently **|p′−p| = d / sin(α/2)** where α is the *interior
dihedral angle between the faces, measured through the material*. Sanity check: α = 90° gives
d√2, the corner of an expanded square. (Derivation; the identity is standard — the SVG 2 spec
gives the same quantity as the miter length `stroke-width / sin(theta/2)`.)

Conversion for this project's convention (visible-side angle V as Gil-Ad measures it):
α = 360° − V; θₙ = 180° − α. Anti-parallel normals (c → −1) means α → 0 — a razor-thin
fin, V → 360° — NOT a wide visible angle. V = 270° (a pillar corner) is α = 90°, ratio √2;
V = 300° is α = 60°, ratio 2.0; V = 250° is α = 110°, ratio 1.22; the "works today" gentle
corners at V ≈ 200–220° are α ≈ 140–160°, ratio 1.02–1.06. Every corner in this scene caps
at 2× the displacement height.

**Degeneracy and the miter limit.** The system is singular as α → 180° (**n₁** ∥ **n₂**);
there, fall back to **u** = *d*·normalize(**n₁**+**n₂**), which is consistent. It blows up as
α → 0. The standard cutoff is 2D stroking's miter limit, and the SVG spec
([w3.org/TR/SVG2/painting.html](https://www.w3.org/TR/SVG2/painting.html)) gives it exactly:
*"miterLength / stroke-width = 1 / sin(theta/2)"*, initial value **4** — below which the join
*"converts from a miter to a bevel"*. A limit of 4 bevels at α < 2·asin(1/4) ≈ 29°. Clipper2's
default is 2 (bevels below 60°) and is the minimum it allows, because "offsets at very acute
angles would generate unacceptably long 'spikes'"
([Clipper2 MiterLimit](https://angusj.com/clipper2/Docs/Units/Clipper.Offset/Classes/ClipperOffset/Properties/MiterLimit.htm)).
The 3D analogue of SVG's `miter-clip` is to emit two vertices and a bevel quad instead of one
mitered vertex.

**Corner vertices (3 planes):** solve the 3×3 system N x = b with rows nᵢ and bᵢ = dᵢ + hᵢ.
Conditioning degrades as 1/|det(n₁,n₂,n₃)| — so a vertex where three near-coplanar strips
meet is the numerically dangerous case, not the hard 90° corner. The plane-translation
formulation is exactly Aurenhammer & Walzl's (*Straight Skeletons and Mitered Offsets of
Nonconvex Polytopes*, Discrete Comput Geom,
[PMC7175731](https://pmc.ncbi.nlm.nih.gov/articles/PMC7175731/)): validity is a
radial-visibility condition (their Lemma 3.2), valid offset surfaces are not unique in general
(saddle vertices of degree 4 admit two resolutions), and Eppstein & Erickson show the 3D
straight skeleton of a general polyhedron is inherently ambiguous
([arXiv:0805.0022](https://arxiv.org/pdf/0805.0022)).

**Convex vs concave, asymmetric consequences (derivation):** at a convex material corner the
offset faces must be *extended* to reach the miter point (spike risk); at a concave one they
must be *trimmed* back to it (self-intersection risk, and whole-face vanishing once d exceeds
local feature size).

**Where self-intersection lives.** Maekawa, *"An overview of offset curves and surfaces"*,
Computer-Aided Design 31:165–173, 1999
([ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0010448599000135)):
offsets *"self-intersect locally when the absolute value of the offset distance exceeds the
minimum radius of curvature in the concave regions"*, and *globally* at a "constriction".
**On a plane the radius of curvature is infinite, so no local self-intersection is possible
inside a face at any amplitude.** All local pathology in the bake is concentrated exactly on
the creases; the only global risk is a wall thinner than twice the amplitude (inference).

**Affordability of general mitered offsetting — decisive.** The state of the art in mitered,
feature-preserving offset meshing (Zhang et al., "Robust and Feature-Preserving Offset
Meshing", [arXiv:2412.15564](https://arxiv.org/abs/2412.15564); ACM TOG as *Feature-Preserving
Offset Meshing*, [doi:10.1145/3797950](https://dl.acm.org/doi/10.1145/3797950)) claims to be
"the first-ever solution for mitered offset that can well preserve sharp features", requires
CGAL rational arithmetic, and reports **6.6 s to 266 s per model** on Thingi10K. Volumetric
approaches (Pavić & Kobbelt CGF 2008; Zint et al. CGF 2023
[doi:10.1111/cgf.14906](https://onlinelibrary.wiley.com/doi/abs/10.1111/cgf.14906); Campen &
Kobbelt CGF 2010) are also not cheap. **Conclusion for a 0.5 s init:** none of the
general-purpose offsetting pipelines fit. What does fit is the local closed-form corner solve
above, applied to a mesh whose plane equations are authored. Jiao's face-offsetting
(*J. Comput. Phys.* 220:612, 2007, [PDF](https://www.ams.sunysb.edu/~jiao/papers/faceoff.pdf))
is the relevant cheap precedent: propagate faces, reconstruct vertices by a local eigenvalue
analysis.

**Production practice at UV seams** is uniformly "don't have them, or force agreement".
RenderMan appnote 12 (*Using Displacement Shaders*, [renderman.jp](https://renderman.jp/appnote.12.html)):
"Any time a piece of geometry is split into two pieces along a new edge, the two sides of the
edge must be displaced exactly the same distance at exactly the same spots"; a second,
independent cause is **texture filtering** — differing micropolygon sizes read different mip
levels, so "the displacement is subtly different on the two sides of the edge"; mitigations:
binary dicing, larger grids, and **disabling texture filtering on displacement lookups**.
V-Ray ships an explicit switch for the floor-meets-wall case, **Keep Continuity** — "tries to
produce a connected surface, without splits, when there are faces from different smoothing
groups and/or material IDs"
([Chaos docs](https://documentation.chaos.com/space/VSKETCHUP/109777787)). Ptex (Burley &
Lacewell, CGF 27(4), 2008, [ptex.us](https://ptex.us/ptexpaper.html)) removes UV unwrapping
entirely but makes *no* formal displacement guarantee ("Border clamping produces a
discontinuity… PRMan will automatically stitch the grids back together"). Htex claims
crack-free displacement by pre-processing texel corners to equal values, valid "whenever
textures have the same resolution". Vector displacement adds a tangent-frame continuity
requirement; Mudbox recommends object space for static geometry
([Mudbox VDM docs](https://help.autodesk.com/cloudhelp/2019/ENU/Mudbox/files/GUID-6182F2EB-99A1-4611-BF48-31EB60D93811.htm)).

**Skirts for genuinely open edges.** Ulrich, *"Rendering Massive Outdoor Scenes in Real-Time:
Chunked LOD"*, SIGGRAPH 2002 course notes ([PDF](https://tulrich.com/geekstuff/sig-notes.pdf))
— vertical skirt triangles at chunk edges, "just high enough to cover any holes". Exact
wording UNVERIFIED against the primary (PDF text extraction failed). Depth rule (from the
construction): the skirt must be at least the maximum possible displacement disagreement across
the edge — the full height-map amplitude. Documented drawbacks: texture stretching on the
skirt, and overlaps visible when looking along the surface plane. The shell/prism alternative:
Porumbescu, Budge, Feng & Joy, *"Shell Maps"*, SIGGRAPH 2005
([PDF](https://web.cs.ucdavis.edu/~porumbes/Pubs/shellmaps_siggraph2005.pdf)) builds the
offset surface with identical connectivity extruded along **shared vertex normals**, so
adjacent prisms share a face exactly.

**A skirt is wrong when the far side has a neighbour** (inference, no source states it): it
adds a self-intersecting inward flap that z-fights the neighbouring patch and *hides* the
misclassification, so the real crack never gets fixed. Classification (E) precedes skirt
emission; the safe default at an ambiguous edge is "shared, weld it", never "open, skirt it".

## C. Normals for the displaced surface

For a **planar** base patch this is exact, not an approximation.

Let (**T**, **B**, **N**) be an orthonormal frame on the plane, with *s_u*, *s_v* the world
units per texture unit along **T**, **B**. Base **S**(u,v) = **O** + u·s_u·**T** + v·s_v·**B**;
displaced **P** = **S** + h(u,v)·**N**. Then:

```
∂P/∂u = s_u·T + h_u·N
∂P/∂v = s_v·B + h_v·N
n = ∂P/∂u × ∂P/∂v = s_u s_v·N − s_v h_u·T − s_u h_v·B
```

Dividing by *s_u s_v*:

```
n ∝ N − (h_u/s_u)·T − (h_v/s_v)·B  =  N − ∇ₛh
```

where ∇ₛh is the surface gradient in **world-length** units. Because ∂**N**/∂u = ∂**N**/∂v = 0
on a plane, no term was dropped — **this is exact.** This is Mikkelsen's surface-gradient form
(Mikkelsen, *"Bump Mapping Unparametrized Surfaces on the GPU"*, 2010,
[mm_sfgrad_bump.pdf](https://mmikk.github.io/papers3d/mm_sfgrad_bump.pdf); exposition at
[zero-radiance.github.io](https://zero-radiance.github.io/post/surface-gradient/)); the origin
is Blinn, *"Simulation of Wrinkled Surfaces"*, SIGGRAPH 1978. Blinn's tangent-perturbation
form is an *approximation* on curved surfaces because it drops ∂**N**/∂u; on a plane it is
exact.

**Scale factor.** If the 8-bit map stores ĥ ∈ [0,1], amplitude *A* world units, and the
texture is *k* texels per world unit along **T**, then h_u/s_u = A·k·(∂ĥ/∂texel). Getting this
wrong tilts every normal uniformly — the "too flat" / "too harsh" bug, independent of any
geometry defect.

**Take the gradient at the same filtered level as the displacement**, or geometry and shading
disagree. Nießner & Loop, *"Analytic Displacement Mapping using Hardware Tessellation"*, ACM
TOG 2013 ([abstract](https://graphics.stanford.edu/~niessner/niessner2013analytic.html)) frame
the entire paper around this and derive normals directly from the displacement function.

**Why averaging across a crease is wrong — the precise argument.** At a crease the surface
is not differentiable; the one-sided normal limits differ, so no single vector represents
both. Max, *"Weights for Computing Vertex Normals from Facet Normals"*, JGT 4(2), 1999
([PDF](https://escholarship.org/content/qt7657d8h3/qt7657d8h3.pdf?t=ptt283)) derives weights
*"appropriate to, and tested for, the situation when the smooth surface is locally represented
near the vertex by a height field approximated by a Taylor series polynomial."* A crease
violates the premise; so do Gouraud's and Thürmer & Wüthrich's weights (see Jin, Lewis & West,
The Visual Computer 21, 2005). **The question is malformed at a crease, not the weights.**

**The correct object** is a per-face-per-vertex normal — one *position*, several *normals*
("split normals"; smoothing groups). Blender's
[Smooth by Angle](https://docs.blender.org/manual/en/latest/modeling/modifiers/normals/smooth_by_angle.html)
is the standard rule: smooth below a maximum angle between face normals, hard above. Artist
practice puts the threshold around 45° with 90°+ always split (UNVERIFIED as a standard).

## D. Per-plane height-field grids

*(Sub-reader's report; sources not independently re-fetched.)*

**Plane registry.** Variational Shape Approximation (Cohen-Steiner, Alliez & Desbrun, TOG
23(3), 2004, [PDF](https://www.geometry.caltech.edu/pubs/CAD04.pdf)) is the closest fit: Lloyd
iteration over *triangles*, proxy P_i = (X_i, N_i), metric L^{2,1} = ∫‖n(x) − n_i‖²dx. The
optimal L^{2,1} proxy normal is simply the **area-weighted average of the region's face
normals**. Partitioning is distortion-minimizing flooding via a global priority queue,
O(N log N) per iteration, converging in "two to twenty iterations", with incremental
farthest-point initialization explicitly recommended for "meshes of mechanical parts". Its
meshing stage doubles as the junction rule: an anchor at every original vertex where ≥3
regions meet, ≥3 anchors per region boundary, anchor position = average of its projections
onto each incident proxy. VSA answers the curved-strip question directly: it **merges**
near-coplanar strips into one chart whenever their normals fit the proxy's budget; chart count
is controlled by *k* or the distortion tolerance, not by strip count.

Efficient RANSAC (Schnabel, Wahl & Klein, CGF 26(2), 2007) is paywalled; the reference
implementation's working values are ε = 0.01× cloud scale, normal threshold 0.9 (cosine,
≈25.8°). *Inference:* whether N strips of chord *c* on a wall of radius *R* merge is decided
by ε versus the sagitta (Nc)²/(8R).

**Lattices and the shoulder problem.** Garland & Heckbert, *"Fast Polygonal Approximation of
Terrains and Height Fields"*, CMU-CS-95-181 ([PDF](https://www.mgarland.org/files/papers/scape.pdf)).
§3.2, verbatim: they *"performed an initial smoothing pass with a Gaussian filter and computed
derivatives on this smoothed function… (points were still selected from the original
unsmoothed version)"* — **decide *where* to sample from the blurred field, read the *value*
from an unblurred source.** Their Algorithm IV uses data-dependent triangulation (Dyn, Levin &
Rippa, IMA J. Numer. Anal. 10, 1990), whose result is that *"long and thin triangles, which
are traditionally avoided, are sometimes very suitable"* — slivers running *along* a mortar
line are correct, not a defect.

The GIS mechanism for feature-aligned grids is **breaklines with constrained Delaunay**
([ArcGIS TIN fundamentals](https://desktop.arcgis.com/en/arcmap/latest/manage-data/tin/fundamentals-of-tin-triangulation.htm)).
Insert mortar-joint centrelines — and, arguably, a *pair* of constrained edges straddling each
block boundary.

Directly on the shoulder defect: Adobe's
[US11600044B2](https://patents.google.com/patent/US11600044B2/en) states *"utilizing bilinear
filtering with the displacement map often smooths out sharp features"* and fixes it with a
per-texel sharpness map that zeroes interpolation coefficients across a discontinuity. Tevs,
Ihrke & Seidel, *"Maximum Mipmaps"*, I3D 2008 ([doi](https://dl.acm.org/doi/10.1145/1342250.1342279))
supplies a conservative max-pyramid. *Derivation:* a mip-2 texel averages 4×4 level-0 texels,
so bilinear reconstruction spreads a block edge over ≈8 level-0 texels; a node on a block
boundary reads the plateau/groove midpoint — the over-carve (the measured −0.036 u plateau
bias). Structural fix: place plateau nodes ≥4 level-0 texels inside the block, and read
plateau nodes from a **max**-pyramid, groove nodes from a **min**-pyramid.

**Adaptive density and stitching.** Restricted quadtree (Von Herzen & Barr, SIGGRAPH 1987):
balance so adjacent cells differ by at most one level, then triangulate with a fixed pattern
chosen by neighbour levels. ROAM (Duchaineau et al., Vis'97,
[PDF](https://www.classes.cs.uchicago.edu/archive/2003/fall/23700/docs/roam.pdf)): *"no special
efforts are needed to avoid cracks or T-vertices"* because a split *forces* its base neighbour
to split first. Geometry clipmaps (Losasso & Hoppe, SIGGRAPH 2004,
[PDF](https://hhoppe.com/geomclipmap.pdf)): *"To stitch adjacent levels into a watertight mesh,
we use the simple solution of rendering zero-area triangles along the render region
boundaries"*, noting that morphing alone leaves T-junctions that *"still result in dropped
pixels."* For bitwise identity across independently gridded charts, Castaño's analysis
([ludicon.com](http://www.ludicon.com/castano/blog/2010/09/precise/), echoed by
[AMD GPUOpen](https://gpuopen.com/learn/gpu-view-adaptive-subdivision/)) is operative: match
the order of operations from both sides and suppress FMA contraction. Purnomo et al.,
*"Seamless Texture Atlases"*, SGP 2004 is the parameterization-side analogue.

**Facades — a useful negative.** Müller et al. 2007, *"Image-based Procedural Modeling of
Facades"* ([PDF](https://www.cs.hunter.cuny.edu/~ioannis/3DP_S09/mueller_facades_2007.pdf))
does **not** derive displacement from a height map; depth is authored per element cluster.
The transferable idea is CGA's **snap lines** (Müller et al., SIGGRAPH 2006): *"(1) For the
repeat rule the snap lines divide the scope into different parts and the repeat rule is
invoked for each part separately. (2) For a subdivision rule the snap line just alters the
closest split."* Production practice (Houdini Convert HeightField, Substance, UE5 Nanite) is
uniformly *uniform*. **No published bake-time, feature-aligned wall-displacement recipe was
found — that gap appears real.**

## E. Robust edge classification

The classification needed is a **4-tuple per edge**, not a single enum: (face count, material
agreement, coplanarity, crease angle). Collapsing these is what produced failure mode 4.

**Face count** is the only topological fact. libigl's `is_edge_manifold`: every edge is
incident on one face (boundary) or two *oppositely oriented* faces
([is_edge_manifold.h](https://github.com/libigl/libigl/blob/main/include/igl/is_edge_manifold.h)).
Material identity and coplanarity are **attributes of the two faces**, never evidence about
how many there are. An edge with two faces of different materials is a *material seam*, not a
boundary; an edge with two coplanar faces is a *coplanar seam*, not a boundary. Dudash's
"intra-material cracking" is the same observation from the renderer's side.

**Welding is the tolerance trap.** CGAL's `stitch_borders()` pairs border halfedges only on
**exact point equality** ([CGAL PMP repair](https://doc.cgal.org/latest/PMP_Mesh_repair/index.html));
libigl's `remove_duplicate_vertices` quantizes coordinate-wise (order-independent, but two
vertices straddling a grid line never merge) and its tracker documents that welding *creates
degenerate faces* ([issue #1078](https://github.com/libigl/libigl/issues/1078)); Blender's
Merge by Distance clusters (transitive closure — a chain of near-duplicates collapses
arbitrarily far); MeshLab's default threshold is 1/10000 of the bounding-box diagonal. The
pitfall stated precisely: an ε-ball relation is *not* an equivalence relation, so every
implementation silently picks chaining or quantization, and **neither is order-independent
and boundary-safe**. Rossignac & Borrel's vertex clustering explicitly allows the topological
type to change. Choose ε relative to the shortest edge, never in world units, and refuse to
weld if ε exceeds a fraction of it. **Practical recommendation for authored geometry:** exact
equality (bitwise or single-ULP hash) as the primary stitch, ε-welding only as an instrumented
fallback that reports what it merged. A material seam is then trivially an edge with exactly
2 incident faces of differing material — the case needing dominant-data / Keep-Continuity
treatment, not a skirt. Survey reference: Attene, Campen & Kobbelt 2013 (full text not
obtained; its specific tolerance warnings UNVERIFIED). Tao Ju, *Fixing Geometric Errors on
Polygonal Models: A Survey*, JCST 24(1), 2009
([PDF](https://www.cs.wustl.edu/~taoju/research/repairsurvey.pdf)) for gap/stitch definitions
(Barequet & Sharir: optimal gap stitching is NP-hard; Borodin, Novotni & Klein 2002:
progressive gap closing by vertex–*edge* contraction, which pure vertex welding cannot do).

**T-junctions.** Detection: distance from the vertex to the segment ≤ ε with the projection
parameter strictly interior, ε scaled to the edge length. Repair: split the long edge at the
projected point (locally correct for planar patches), or constrained retriangulation.
**Why they crack:** Direct3D's rule is that "the top-left rule ensures that adjacent
triangles are drawn once"
([Rasterization Rules](https://learn.microsoft.com/en-us/windows/win32/direct3d11/d3d10-graphics-programming-guide-rasterizer-stage-rules))
— conditional on both triangles presenting the *same* edge (same endpoints, same fixed-point
edge function). A T-junction breaks the precondition: the long edge and the two short edges
are three different segments, and after snapping the coverage decisions no longer complement
— a one-pixel row is claimed by neither. Grazing incidence turns one texel of displacement
disagreement into many pixels of gap. **Implication for the bake: T-junctions must be
eliminated BEFORE displacement** — displacing a T-vertex by its own sampled height, while the
long edge interpolates between two other heights, converts a sub-pixel raster crack into a
full-amplitude geometric hole. Half-edge structures encode boundaries by a null face pointer,
never a null twin ([Stanford CS268 notes](https://graphics.stanford.edu/courses/cs268-13-spring/Notes/halfedge.pdf)),
and only represent orientable manifolds — the build failing is the diagnostic.

## G. The union-of-offset-slabs definition, and a ray-marched reference

**The headline is a clean negative, and the most important finding for the design decision.**
No source was found that defines a displaced solid as the union of per-face offset slabs
partitioned by a Voronoi/bisector rule, with an explicit castellated step where adjacent
faces' heights differ. **The candidate definition is not in the literature.** Every crack-free
construction that could be verified does the opposite: it either forces the two sides to
agree on one height value at the shared edge, or builds a *conforming* shell so no two-sided
decision ever exists.

Four independent lines converge on "make h₁ = h₂ at the shared edge": micro-meshes duplicate
displacement values on shared edges (§A); Mesh Colors (Yuksel, Keyser & House, TOG 29(2), 2010,
[PDF](http://www.cemyuksel.com/research/meshcolors/meshcolors_tog.pdf)) shares vertex and edge
samples outright — *"since the colors along connections of neighboring patches are shared, we
guarantee continuity across edges"*; Htex pre-processes texel corners to equal values;
Purnomo's seamless atlases replicate border texels. Ptex — architecturally the closest system —
makes **no** guarantee and defers the corner to PRMan's downstream stitcher.

**If the dominant-edge rule from §A is enforced — both faces read the *same* height value along
a shared crease — the mitre becomes well-defined (the two offset surfaces genuinely intersect
there) and the union model's castellation step vanishes on its own.** The castellation is
therefore a choice made by *not* enforcing the rule, and it is a departure the literature gives
no cover for; it has to be justified on look. (Synthesis.) Shell maps corrects a premise in the
framing: because the offset surface has identical connectivity extruded along **shared vertex
normals**, adjacent prisms share a face exactly and the convex-gap/concave-overlap question
never arises at a shared edge; concavity is handled *globally* by shortening the offset (Cohen
et al. 1996 envelopes), never by a bisector partition.

**One correction to the extension rule** (derivation): the per-face extension past the authored
edge needed for the bisector partition is **h·cot(φ/2)**, not h — exact only at right-angle
corners, and under-extending on shallow bends.

**Ray-marched ground truth.** Families surveyed in Szirmay-Kalos & Umenhoffer, *"Displacement
Mapping on the GPU — State of the Art"*, CGF 27(6), 2008. Linear search plus binary refinement
(Policarpo, Oliveira & Comba, I3D 2005) and POM (Tatarchuk, I3D 2006) are **not** conservative —
they skip thin features between samples. Conservative marches: cone step mapping (Dummer 2006),
relaxed cone stepping (Policarpo & Oliveira, GPU Gems 3 ch. 18), and quadtree/maximum-mipmap
traversal (Tevs et al., I3D 2008), conservative by construction. **Only per-texel DDA is exact
in the limit**, cost linear in texels crossed. For the SDF formulation: Bálint, Valasek & Gergó,
*"Operations on Signed Distance Functions"*, Acta Cybernetica 24(1), 2019
([PDF](https://people.inf.elte.hu/csabix/publications/articles/acta-2018-sdf-operations.pdf))
prove the offset identity on the *exterior* (Theorem 1) and state that inside the offset volume
"the error can be arbitrarily large"; the same holds for min-as-union. Sphere tracing needs only
a Lipschitz bound (Hart, *"Sphere Tracing"*, The Visual Computer 12, 1996) and is "particularly
adept at rendering pathological surfaces" with discontinuous derivatives. **Since the reference
marches from outside, min is exact and the construction is sound.**

**Validation practice.** Micro-mesh construction's notion is *reprojectability* — the μ-mesh
"must hit [the input surface] with the set of rays defined by the μ-mesh's interpolated
displacement directions"; its error metric is an area-weighted average projection distance,
bbox-normalized (not Hausdorff). Metro (Cignoni, Rocchini & Scopigno, CGF 17(2), 1998) is the
standard sampled-Hausdorff tool. Terminate the march at a patch border by **discard** — what
Policarpo & Oliveira 2006 do.

## Addendum — second pass of the survey (same agent, after the sub-readers reported)

- **DiagSplit's precision trap, verbatim:** "T cannot use information such as numerical
  derivatives on the patch interior. Differences in numerical precision due to different
  subpatch orientations can also lead to inconsistent T evaluations. **Ordering control points
  along an edge by their world space position** can be used to ensure consistent numerical
  evaluation." → derive nothing from an edge before ordering its endpoints canonically.
- **Micro-mesh's direction field** is optimised, explicitly *not* an area-weighted normal
  ("can lead to visible geometric artifacts", their Fig. 5): `V(v) = max_d min_n (d·n)` over
  incident base faces, restricted to strictly positive values; the ±1-level constraint between
  adjacent subdivision levels plus an edge-decimation bit is the bake-side R2.
- **Union-of-slabs as an SDF:** Hart's Eq. 16 gives union as an equality `d(x, A∪B) =
  min{f_A, f_B}` on the exterior; Quilez states the restriction ("only true in the exterior…
  in the interior a lower bound", [distfunctions](https://iquilezles.org/articles/distfunctions/)).
  Sphere-tracing the *displaced* field is a poor reference (`Lip f ≤ √(1+L²)`, the step shrinks
  by the height field's Lipschitz constant) — march in the per-face (u,v,depth) frame instead.
- **Which march is exact, verbatim (Szirmay-Kalos & Umenhoffer 2008):** safe methods
  "guarantee that they do not skip the first intersection, but cannot guarantee that the
  intersection is precisely located if the number of iterations is limited," and "to make
  linear search really safe **each texel needs to be visited**." Relaxed cone stepping *states*
  a first-intersection invariant but Tevs et al. **measured** it failing on thin structures
  (their Fig. 9) — do not use RCS as a reference. Maximum mipmaps with an analytic
  ray/bilinear-patch leaf solve is the defensible fast approximation; per-texel DDA is the
  ground truth.
- **Patch borders:** Szirmay-Kalos: the macrostructure surface should be "thickened" to include
  the volume of the height field above it; the border test "is easy for rectangles, becomes
  more complicated for triangles". Silhouette correctness needs per-vertex quadric
  coefficients (Oliveira & Policarpo 2005) or prisms.
- **Image-space validation precedents:** DiagSplit's Fig. 2 renders back-facing geometry in
  orange so cracks show as orange pixels; Lindstrom & Turk, *Image-Driven Simplification*
  (TOG 19(3), 2000): luminance RMS over fixed view sets, with **front-face culling in half the
  views to expose interior leaks**; Shafiee Sarvestani, Zhou & Wang 2024
  ([arXiv:2405.06143](https://arxiv.org/html/2405.06143v1)): full-reference crack detector —
  truncated difference → local-contrast normalisation → multiply by |Laplacian| → sigmoid.
  **No paper was found that ray-traces the exact displaced definition per pixel and compares it
  against a tessellated raster render as validation** — the proposed gate is near-unprecedented.
- **The two things to weigh before the design (the agent's closing):** (1) whether h₁ = h₂ is
  *enforced* on every shared crease — every crack-free multi-chart system does; enforcing it
  makes the mitre well-defined *and* makes the castellation vanish, collapsing A, B and G into
  one rule; (2) only per-texel DDA is provably exact — budget for it being slow at grazing, and
  take the crack gate from Lindstrom & Turk's front-face-culled views plus the
  Laplacian-weighted map.
- Citation corrections: Hirche et al. 2004 is Graphics Interface (uniform sampling + linear
  zero-crossing; the interval/Bézier bound is Smits, Shirley & Stark 2000); "An Introduction…"
  is Attene et al.'s Eurographics tutorial, not the CSUR paper.
